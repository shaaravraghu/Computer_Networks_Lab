Client-Server Architecture:
Server:
▪ always-on host
▪ permanent IP address
▪ often in data centers, for scaling
Clients:
▪ contact, communicate with server
▪ may be intermittently connected
▪ may have dynamic IP addresses
▪ do not communicate directly with each other

Peer-to-Peer Architecture:
▪ no always-on server
▪ arbitrary end systems directly communicate
▪ peers request service from other peers, provide service in return to other peers
▪ self scalability– new peers bring new service capacity, as well as new service demands
▪ peers are intermittently connected and change IP addresses
▪ complex management

Process Communication
process: program running within a host
- within same host, two processes communicate using inter-process communication (defined by OS)
- processes in different hosts communicate by exchanging messages
client process: process that initiates communication
server process: process that waits to be contacted

HTTP (HyperText Transfer Protocol)
HTTP is a simple, synchronous request/reply protocol
HTTP is layered over a bidirectional byte stream, typically TCP 
HTTP is text-based (ASCII) – human readable, easy to reason about
HTTP is stateless – it maintains no info about past client requests
Based on Client-Server Model
Methods: GET (pull data) and POST (push data)

SMTP (Small Mail Transfer Protocol) Protocol between mail servers (built on top of TCP)
3 Phases of SMTP
- hand-shaking (greeting)
- transfer of messages
- closure
Types of Agents:
- Mail User Agent (read/ write emails)
- Mail Submission Agent (process and forward to MTAs)
- Transmission Agent (queues, receives and sends mail to other MTAs)
- Message Delivery Agent (deliver mail to mailbox)
- Retrieval Agent: Fetches email from user mailbox
- Message Transfer Agent (Proxy for SMTP Protocol)

POP (Post Office Protocol): used to support users with intermittent network connectivity
3 Phases:
Authenticate
Transaction 
Update

IMAP (Internet Messaging Access Protocol)
- complete and complex mailbox system (always ON)

Message Format: MIME: Multipurpose Internet Mail Extension
- Version, Description, ID, Type, Transfer-Encoding

CDNs: Content Delivery Networks

DASH: Dynamic Adaptive Screening over HTTP
- for streaming multimedia

(constant bit rate server) <- variable network delay (time axis) -> (client video reception) <- client playout delay (time axis) & buffered video (data axis) -> (constant bit rate client)

FTP (File Transfer Protocol)
- Active Mode: server chooses port and client establishes TCP
- Passive Mode: server selects a random port
Data transfer modes:
- Stream mode: continuous stream of data
- Block mode: sent in blocks
- Compressed mode: certain algorithms

Socket: Endpoint of Communication
- UDP (User Datagram Protocol): unreliable datagram
- TCP (Transfer Protocol): reliable, byte stream-oriented
Stream Socket: connection-oriented socket
Datagram socket: connectionless socket

Socket: Create a new connection endpoint
Bind: Attach a local address to a socket
Listen: Announce willingness to accept connections
Accept: Block caller until a connection request arrives
Connect: Actively attempt to establish a connection
Send: Send some data over the connection
Receive: Receive some data over the connection
Close: Release the connection
